**Who uses which LLM / vendor**

| Deployable | LLM | Map / place vendors | Weather |
| --- | --- | --- | --- |
| what2eat / where2play BFF | Product Quanzil (`OPENAI_*` on that app) | None — call places-agent | None — call places-agent if needed |
| places-agent | Agent Quanzil (`OPENAI_*` on the agent) | AMAP, Google (direct or MCP fallback), Tripadvisor | Open-Meteo only; localize output |

Rules: minimal dependencies; prefer platform and stdlib; pick only the third-party capabilities a product needs. Secrets never ship to either browser (ADR-002). LLM is **not** destination-routed (ADR-004). Place vendors are **caller-driven** `providers[]` (ADR-005) — this spec does not force mainland → AMAP.

## Minimum dependencies policy

- Use as few dependencies as possible — prefer the platform, stdlib, and existing stack before adding packages.
- Keep the architecture clean: no optional libs “just in case.”
- Do not add a fourth deployable for admin UI, weather, or Maps MCP (those are capabilities of places-agent / the Worker).

## 3rd party capabilities and API

### Quanzil Chat capability: `OPENAI_CHAT_MODEL`

Quanzil is the OpenAI-compatible gateway. Do **not** call `api.openai.com`. Env names stay `OPENAI_*` (ADR-004).

- API Configuration
  - Provider=`Quanzil` (OpenAI-compatible)
  - Model-name=`OPENAI_CHAT_MODEL` (inventory default `gpt-5.4`)
  - Host=`OPENAI_HOST` / `quanzil.com`
  - API-Key=`OPENAI_API_KEY`
  - Base_URL=`OPENAI_BASE_URL` (inventory `https://quanzil.com/v1`)
  - Key mgmt=`OPENAI_KEY_MGMT_SITE` (inventory `https://quanzil.com/console/token`)
- Technical highlights
  - Client: `openai` SDK with `baseURL` = `OPENAI_BASE_URL`
  - Endpoint: `/chat/completions`
  - Param: `max_completion_tokens` (**not** `max_tokens`)
  - places-agent: tool-loop / NL place chat on **its** server env
  - Apps: product UX LLM on **that app’s** BFF env — never the browser
  - Optional other Quanzil models (e.g. `gemini-2.5-flash` via the same gateway) may exist in the key inventory for experiments; they are **not** destination routing
  - On failure: return error to caller — never silent empty success
  - Product behavior: see project requirements doc

### Quanzil Image capability: `OPENAI_IMAGE_MODEL`

Used only by products that generate or edit images. places-agent MVP tools do **not** require image.

- API Configuration
  - Model-name=`OPENAI_IMAGE_MODEL` (inventory default `gpt-image-1.5`)
  - Same `OPENAI_API_KEY` / `OPENAI_BASE_URL` as chat
- Technical highlights
  - Endpoint: Quanzil `/images` via `openai` SDK — generation and/or edit per project
  - Params: only API-documented sizes (e.g. `size: "1024x1536"`) and `quality: "low"` when supported — never invent dimensions
  - **Performance tuning (≤20s component target; soft UI tip ~10s — see Performance):**
    - Keep **`quality: "low"`** and documented portrait size only
    - Request **`n: 1`**; no parallel duplicate image calls for the same logical output
    - **Downscale reference images on the server** before edit (cap long edge ~1024px)
    - **Short, structured prompts** — task summary only
    - Do **not** serialise text LLM and image on one critical path when text is already available
    - Reuse a single `openai` client; outbound **HTTP timeout ~25s** — do **not** add a separate **10s hard abort**
    - Retry: **one** explicit user-triggered retry max per attempt path
  - On failure: return error to caller — never silent empty image
  - Product behavior: see project requirements doc

### 高德地图 (AMAP) capability: 高德开放平台 Web 服务

Verified against [高德 Web 服务概述](https://lbs.amap.com/api/webservice/summary), [地点搜索 2.0](https://lbs.amap.com/api/webservice/guide/api/newpoisearch), [地理/逆地理编码](https://lbs.amap.com/api/webservice/guide/api/georegeo), [路径规划](https://lbs.amap.com/api/webservice/guide/api/direction/), [天气查询](https://lbs.amap.com/api/webservice/guide/api/weatherinfo), and [坐标系 FAQ](https://lbs.amap.com/faq/advisory/others/39840/).

- API Configuration
  - Platform=`AMap (Gaode / 高德地图)`
  - Host=`AMAP_HOST` = `restapi.amap.com`
  - Base_URL=`AMAP_BASE_URL` = `https://restapi.amap.com`
  - API-Key=`AMAP_API_KEY` — must be a **Web 服务 API** key (not a JS API / Android / iOS key)
  - Key mgmt=`AMAP_KEY_MGMT_SITE` = `https://lbs.amap.com/`
- Endpoints (server-side on places-agent)

  | Need | Method / path |
  | --- | --- |
  | Keyword search | `GET /v5/place/text` |
  | Nearby search | `GET /v5/place/around` |
  | Place by id | `GET /v5/place/detail` (or v3 `place/detail`) |
  | Geocode | `GET /v3/geocode/geo` |
  | Reverse geocode | `GET /v3/geocode/regeo` |
  | Driving route | `GET /v3/direction/driving` or `GET /v5/direction/driving` |

- Technical highlights
  - **Key type:** Web 服务. JS API keys and security codes (`securityJsCode`) are for browser maps, not this adapter.
  - **Coordinates:** `location` / `origin` / `destination` are **lng,lat** (longitude first), ≤6 decimal places. Do not send Google-style `lat,lng`.
  - **CRS:** 高德坐标系 (GCJ-02) in CN / HK / MO / TW; WGS-84 overseas ([FAQ](https://lbs.amap.com/faq/advisory/others/39840/)). Convert GPS/WGS-84 mainland points via `GET /v3/assistant/coordinate/convert` (`coordsys=gps`) before search/route. Do not mix Google WGS-84 pins into AMAP calls without conversion.
  - **Dining filter:** POI `types` `050000` (餐饮服务) for `search_restaurants`.
  - **Coverage:** strong in mainland China; HK/MO/TW use 高德 CRS; overseas POI/map is a separate 世界地图 permission and is **not** the default for this family. Tripadvisor remains the review enricher — AMAP does **not** replace Tripadvisor.
  - **Weather:** do **not** call AMAP `weatherInfo`. Weather is Open-Meteo only ([ADR-014](./adr/ADR-014-open-meteo-weather.md)).
  - **Trust:** key only on places-agent. Deeplinks must be secret-free.
  - **Selection:** callers pass `providers[]` including `AMAP`. Do **not** auto-switch to AMAP because the destination is in mainland China (ADR-005).
  - On failure: return error / skip with reason — never silent empty success
  - Product behavior: see project requirements doc

### Google Maps Platform capability: Maps Platform (direct)

Primary Google path when places-agent can reach `maps.googleapis.com` (expected from 野草云3).

- API Configuration
  - Platform=`Google Maps Platform`
  - Host=`GOOGLE_MAPS_HOST` = `maps.googleapis.com`
  - API-Key=`GOOGLE_MAPS_API_KEY`
  - Project=`GOOGLE_MAPS_PROJECT`
  - Base_URL=`GOOGLE_MAPS_BASE_URL` (Places New, Geocoding, Routes, Time Zone as documented)
  - Key mgmt=`GOOGLE_MAP_KEY_MGMT_SITE`
- Technical highlights
  - APIs: Places API (New) text/nearby/details, Geocoding, Routes / Directions, Time Zone. Maps JavaScript / Embed only via **server-issued** config if an app needs a map widget.
  - Do **not** add `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`. Place photos via server proxy; no Maps key in client `img` URLs or deeplinks.
  - CRS: WGS-84. Do not send AMAP GCJ-02 coords into Google without conversion.
  - **Weather:** Google Weather API (`weather.googleapis.com`) is a separate paid product with **no mainland CN coverage**. Do not enable it. Weather is Open-Meteo only ([ADR-014](./adr/ADR-014-open-meteo-weather.md)).
  - On direct failure (timeout, connection reset, persistent 403/502 from egress): fall back to [Google Maps Cloudflare Worker MCP](#google-maps-cloudflare-worker-mcp-fallback). Do not fall back to AMAP unless the caller asked for `AMAP`.
  - On failure after fallback exhausted: return error / skip with reason
  - Product behavior: see project requirements doc

### Google Maps Cloudflare Worker MCP (fallback)

Use when the caller requested `GOOGLE_MAPS` but **direct** Google REST from places-agent is unreachable. This is a **transport fallback for Google data**, not a fourth place vendor and not an AMAP replacement.

- API Configuration
  - Service=`Google Maps MCP` (Cloudflare Worker, Streamable HTTP)
  - Host=`GMAPS_MCP_HOST`
  - Base_URL=`GMAPS_MCP_URL` (inventory path `/mcp`)
  - API-Key=none on the agent
  - Bearer=`GMAPS_MCP_BEARER` (`Authorization: Bearer …`)
- Technical highlights
  - Transport: Streamable HTTP MCP (JSON-RPC). Discover tools with `tools/list` before first call; do not assume tool names from another MCP.
  - The Worker holds the Google Maps Platform key. places-agent sends only the MCP bearer — never `GOOGLE_MAPS_API_KEY` to the Worker, and never the bearer to browsers.
  - Same adapter contract as direct Google: search, details, geocode, directions. Tag provenance as `GOOGLE_MAPS` (not a separate `GMAPS_MCP` provider id).
  - Order: **direct Google → this MCP**. Skip MCP when direct succeeds. If MCP is unconfigured, skip Google with `errors.provider_unconfigured` / `errors.provider_failed` as appropriate.
  - Mainland **client** still may be unable to open Google Maps app/web; that is a deeplink/UI concern (ADR-006), not solved by this Worker.
  - On failure: return error / skip with reason — never silent empty success
  - Product behavior: see project requirements doc

### Tripadvisor Terra capability: Terra API

- API Configuration
  - Service=`Tripadvisor Terra`
  - Host=`TRIPADVISOR_HOST` = `terra.tripadvisor.com`
  - API-Key=`TRIPADVISOR_API_KEY` (header `X-API-Key`)
  - Base_URL=`TRIPADVISOR_BASE_URL` = `https://terra.tripadvisor.com/api`
- Technical highlights
  - Endpoints: `GET /locations/nearby` · `GET /locations/{id}` · `GET /locations/{id}/reviews`
  - Params: `lat` + `lon` (not `latLong`); `radius`; `unit=KM` (uppercase)
  - Do **not** call Content API host `api.content.tripadvisor.com` with a Terra key
  - Match by **name + location** — **never** pass Google `place_id` (or AMAP id) as a Tripadvisor place id (ADR-007)
  - Flatten localized name/review fields to plain strings before returning to callers
  - Best-effort enrich; failures must not wipe primary search results
  - On failure: omit enrichment with reason — never silent broken UI
  - Product behavior: see project requirements doc

## Weather

Weather is a **supporting** capability for itinerary / “go-out” context. It is not a map vendor and is not selected via `providers[]`. Binding: [ADR-014](./adr/ADR-014-open-meteo-weather.md).

**Provider:** Open-Meteo only. Do not call AMAP `weatherInfo` or Google Weather API.

- API Configuration
  - Service=`Open-Meteo`
  - Host=`OPEN_METEO_HOST` = `api.open-meteo.com` (commercial: `customer-api.open-meteo.com`)
  - Base_URL=`OPEN_METEO_BASE_URL` = `https://api.open-meteo.com/v1`
  - API-Key=`OPEN_METEO_API_KEY` (required on the customer host; none on the free host)
  - Docs=`OPEN_METEO_DOCS` = `https://open-meteo.com/en/docs`
- Call: `GET /forecast` from places-agent. Example params: `latitude` · `longitude` · `current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m` · `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max` · `timezone=auto`
- Commercial: same query shape on `https://customer-api.open-meteo.com/v1` + `apikey`. Show Open-Meteo attribution ([licence](https://open-meteo.com/en/licence)).
- On failure: return error to caller — never silent empty success. Do not substitute AMAP or Google weather.

### Open-Meteo is English / WMO — translate before display

Open-Meteo has **no language parameter**. The forecast body is numeric (`weather_code`, °C, %, m/s). Human-readable names in their docs are **English** (e.g. “Slight rain showers”). That is **not** Layer B vendor copy (place names may stay English if the map vendor returned English). Weather labels **must** be translated.

| Layer | What to do |
| --- | --- |
| Payload (machine) | Keep `weather_code` and numeric measurements. Provenance `provider: OPEN_METEO`. |
| Layer A — condition text | Map `weather_code` → catalog key `weather.wmo.{code}` in `EN` / `CN` / `HK` / `TW`. HK vs TW wording must differ where the glossary requires it (e.g. 驟雨 vs 陣雨). |
| Layer C — numbers | Format temp / wind / humidity / dates with `Intl` for the request locale. Do not concatenate English unit words (`"km/h"`) into CN/HK/TW strings; use catalog unit keys. |
| Layer L — LLM | Pass **localized** condition strings (or code + locale) into chat / itinerary narrative. Do **not** paste English Open-Meteo phrases into `CN` / `HK` / `TW` prose. |
| Fallback | Missing catalog entry → `EN` → key `weather.wmo.{n}`. Do not fail the whole itinerary solely for a missing weather string. |

Rejected alternatives (kept for the record, not wired): AMAP weather is city **adcode** only; Google Weather has **no mainland CN** coverage and is a separate billed API.

### Decision (locked)

| Stage | Choice |
| --- | --- |
| **Weather provider** | Open-Meteo `GET /v1/forecast` on places-agent |
| **AMAP / Google weather** | Do not adopt |
| **Display language** | Catalogs + formatters + locale-aware LLM; never raw English Open-Meteo labels except when locale is `EN` |

## Performance

Image generation has additional tuning — see Quanzil Image.

**Latency (all components — one contract only):**

- Soft tip: after ~**10s**, show “more time is needed” while work continues (never the word “Timeout”)
- Target: each component ready within **≤20s**
- Do **not** implement a separate conflicting 10s hard timeout that abandons the component early without a user-visible state

**Loading strategy (all components):**

- Fetch in **parallel** across independent components (place search vs weather vs LLM narrative)
- **Stream / render** each piece as it completes — do not block the whole view on the slowest component
- Show **per-component** tips and progress while work is pending

**Fallbacks:**

- Google Maps: direct REST, then Worker MCP — only on upstream failure, not at the 10s soft tip
- Weather: Open-Meteo only — do not silently swap to AMAP/Google at ~10s
- Use **local fallbacks** only when upstream fails or the component is still empty after the user-visible wait path

## Implementation pitfalls (must follow)

Cross-check when implementing against the project requirements doc:

| Area | Contract |
| --- | --- |
| **Chat** | Quanzil via `OPENAI_*` + `openai` SDK `baseURL` — **not** `api.openai.com`. Use `max_completion_tokens`, not `max_tokens` |
| **Image** | Documented sizes and `quality: low` only when applicable; never silent image failure |
| **AMAP** | Web 服务 key; `lng,lat`; GCJ-02 in CN/HK/MO/TW; `types=050000` for dining; not a Tripadvisor replacement; not a geo-forced default |
| **Google Maps** | Single server `GOOGLE_MAPS_API_KEY` — no `NEXT_PUBLIC_*`. Direct first; Cloudflare Worker MCP (`GMAPS_MCP_*`) on egress failure |
| **Tripadvisor** | Terra host only; name+location match; never Google/AMAP id passthrough |
| **Weather** | Open-Meteo only (ADR-014). Map `weather_code` → `weather.wmo.{code}` in `EN`/`CN`/`HK`/`TW`. Do not pass English Open-Meteo labels through; do not call AMAP/Google weather |
| **Latency** | Soft tip ~10s · target ready ≤20s — **one contract only** |
| **Secrets** | Env / Portainer only — never commit real keys; never put map keys, Quanzil, MCP bearer, or caller-key plaintext in the browser |

## Localization (i18n)

This family **is** bound by workspace i18n (ADR-011): catalogs `EN`, `CN`, `HK`, `TW`; no OpenCC; HK and TW wording must differ on pinned keys. Vendor **place** names/addresses pass through with provenance (Layer B). **Weather is not Layer B:** Open-Meteo responds in English/WMO codes — translate via `weather.wmo.{code}` and formatters (ADR-014).
