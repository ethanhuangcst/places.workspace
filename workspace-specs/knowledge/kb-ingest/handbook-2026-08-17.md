# Places workspace knowledge handbook (refresh 2026-08-17)

Supersedes the earlier kb item titled “Places workspace knowledge handbook” that stopped at ADR-010 and described three runtimes. Prefer this copy. Binding decisions remain the ADRs.

Reusable lessons, not product AC. No secrets.

## Spec and workspace split

Umbrella specs are product-family wide; places-agent requirements stay agent-only; architecture holds trust boundaries and deploy. Parent git tracks specs only; folder is places-workspace.

Delivery slices follow agent capabilities (ADR-018), not “admin vs gateway vs intelligence.” All admin UI (Features 14–19) is MVP-1.

## Naming

Machine-readable agent id is `places-agent` (host places.agent-mate.ai). MCP serverInfo.name and HTTP JSON field `agent` MUST be this string (ADR-013). Hostname is not a substitute. Do not revive geo-capability-route.json. Rejected family names: place-agent, fun-place-agent, play-service, what2eat-agent.

## Three region axes (do not collapse)

- Search destination: where the place search is about — does not alone force vendors.
- Client environment: where the browser/user is — app UI picks deeplinks.
- Deploy/egress: where the server runs and which APIs it can reach — ops/env, not product provider policy.

## Place providers, provenance, Tripadvisor

Callers pass providers[] (and enrich/merge); agent tags sources[]; UI picks nav deeplinks by client environment. Hard destination router (mainland → AMAP) is superseded (ADR-005).

Tripadvisor: match by name + location. Never pass Google place_id as a Tripadvisor id. Best-effort; failures must not wipe primary search.

Google transport: direct maps.googleapis.com first; Cloudflare Worker MCP only on egress failure. Provenance stays GOOGLE_MAPS (ADR-017). Worker is not a fourth vendor and not AMAP-when-Google-fails.

## OPENAI_CN / LLM

Product and agent LLM use OPENAI_CN via openai SDK. Env names stay OPENAI_*. Base URL is OPENAI_CN (`OPENAI_BASE_URL` (set per deployable for OPENAI_CN; do not hardcode host)), not api.openai.com. LLM is not switched by search destination. places-agent has its own OPENAI_*; apps have theirs on the BFF. Browser never holds keys.

## Trust boundaries

Four runtimes: consumer browser, operator browser, app BFF, places-agent. Secrets never ship to either browser.

- Consumer browser → same-origin app API → agent (caller key) / product OPENAI_CN.
- Operator browser → same-origin places.agent-mate.ai (admin session) for users and caller keys — never map-vendor keys.
- Admin session is not a caller API key. Map/Tripadvisor keys only on places-agent env.

Operator chrome is the kb.agent-mate.ai 性冷淡 family (logo on #fafafa, locale switcher EN CN HK TW). After login, default landing is Caller API keys.

## Deploy on 野草云3 (Option 1)

Three services / three images / three Portainer stacks: what2eat, where2play, places-agent. Operator admin UI is inside the places-agent image (same hostname), not a fourth stack.

places-agent: one hostname → one container (no kb-style NPM Custom Locations). kb-agent still uses Custom Locations because web and agent are two containers.

places-agent stack also needs: Resend + session secret in env; SQLite on a volume (ADR-015); process entry server.ts (ADR-016); default admin seed on first boot (username admin; do not bake a password into the image).

Domains: what2eat.food, where2play.place, places.agent-mate.ai (admin + HTTP + MCP).

## Workspace layout

Parent: places-workspace — umbrella specs only. Children are separate remotes, gitignored from parent: 0.1.sdd.sample, 0.2.release-bot, 1.places-agent, 2.what2eat, 3.where2play. 0.1.sdd.sample origin is github.com/ethanhuangcst/sdd.sample.git (not sdd-example.git).

## Locales (HK vs TW)

HK and TW are independent Traditional Chinese locales. Do not OpenCC-convert catalogs. Never fall back HK↔TW; fallback is requested locale → EN → raw key.

Three layers: agent copy (catalogs), vendor facts (languageCode; do not rewrite POI names), formatters (Intl + real currency from place country). LLM narrative loads a small glossary on demand. HK chrome is 書面語, not 口語.

Weather is Open-Meteo only (ADR-014): WMO codes are Layer A (weather.wmo.{code}), not Layer B pass-through.
