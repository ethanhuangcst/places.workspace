## 1. Purpose & scope

This document defines system structure, trust boundaries, provider gateway behavior, deploy shape, and workspace layout. It does not replace product requirement docs for what2eat or where2play.

**In scope:** three deployables; places-agent core (tools + **operator management web** on the same host); caller-driven providers; result provenance; itinerary ownership; Option 1 deploy on 野草云3; umbrella git.

**Out of scope here:** pixel-level UI, per-app i18n catalogs, detailed OpenAPI schemas (follow in design/API specs).

## 3. Runtime trust boundaries

Four runtimes: **consumer browser**, **operator browser**, **app BFF**, **places-agent**. Secrets never ship to either browser. Operator HTML is served from `places.agent-mate.ai` and calls **same-origin** admin APIs only.

### Who may call what

| Capability | Consumer browser | Operator browser (`places.agent-mate.ai`) | App BFF | places-agent |
| --- | --- | --- | --- | --- |
| Quanzil (`OPENAI_*`) | No | No | Yes (product UX) | Yes (agent / tools) |
| AMAP / Google / Tripadvisor keys | No | No (not in admin UI) | No | Yes (env) |
| Admin session (cookie) | No | Yes (same-origin) | No | Issues / validates |
| Caller API key (plaintext) | No | Once at create / regenerate, then copy; never stored in the client as the source of truth | Sends on server-to-server calls | Stores hash; validates HTTP/MCP |
| places-agent HTTP tools | Same-origin **app** routes only | No (session ≠ caller key) | Server-to-server + caller key | Serves |
| places-agent MCP | N/A | N/A | Optional | Serves (e.g. chatboxai) + caller key |
| Resend (invite / reset) | No | Triggers via same-origin admin API | No | Yes (env) |
| Nav deep links / logos | Yes (display / open) | N/A | Pass-through | Emits on cards |

### Request flows

```text
# Operator admin (ADR-012)
Operator browser → places.agent-mate.ai (same origin) → session → users / caller keys / instructions
                 → Resend (invite / password reset)

# Place / map work
Consumer browser → app same-origin API → places-agent (caller API key) → AMAP | Google | Tripadvisor

# Product LLM (app-owned)
Consumer browser → app same-origin API → Quanzil (app OPENAI_*)

# Agent LLM
Caller → app BFF or MCP host → places-agent (caller API key) → Quanzil (agent OPENAI_*)
```

## 4. places-agent core

- **Tools (MVP+):** `search_restaurants`, `search_places`, `get_place_details`, `navigate`; geocode as needed; `plan_itinerary` for trip callers.
- **Dual transport:** HTTP API and MCP share one tool core (no forked business logic). Both require a **caller API key**.
- **Adapters:** AMAP, Google Maps, Tripadvisor behind a common place-card shape (`provider` / `sources[]`, deep links).
- **Operator web (same process):** public home, login, post-login landing, admin users, caller API keys, agent instructions, admin i18n. Auth = **admin session**. Does not display map-vendor keys. Public register is off; default admin is seeded on first deploy.
- **One hostname:** `places.agent-mate.ai` serves operator HTML, admin APIs, tool HTTP, and MCP. Path layout is an implementation detail; admin APIs stay same-origin with the admin pages.
- **Caller identity:** machine id **`places-agent`** (ADR-013). MCP `serverInfo.name` and HTTP JSON field `agent` MUST be this string. Hostname `places.agent-mate.ai` is the host, not the id. Tool names stay unprefixed (`search_restaurants`, …).
- **Data:** admin users and caller-key hashes persist in a store bound to this stack (volume or DB). Map-vendor keys, Quanzil, Resend, and session secret stay in env.

## 5. LLM posture

- All product LLM usage uses **OpenAI Quanzil** (`OPENAI_*`) on the **server** of that deployable.
- LLM is **not** destination-routed (no “CN → Qwen, else Gemini”).
- Optional other Quanzil models (e.g. Gemini via Quanzil) may exist in key inventories for experiments; they are not part of destination routing.

## 6. Provider gateway (caller-driven)

**Supersedes** embedded “mainland destination ⇒ AMAP only” geo policy and the former `agent-config/geo-capability-route.json` region matrix as a hard router. That file is **removed**; do not recreate it.

| Rule | Detail |
| --- | --- |
| Selection | Caller passes `providers[]` (and related options: enrich, merge) |
| Agent role | Multi-provider gateway: validate, call adapters, tag results |
| Failures | Missing credentials / unsupported capability → explicit error or skip with reason |
| Config | Secrets only in env; capability matrix in docs/config for *what each vendor can do*, not “where to force” |

Example (conceptual):

```json
{
  "query": "ramen",
  "near": { "lat": 22.3, "lng": 114.2 },
  "providers": ["GOOGLE_MAPS"],
  "enrich": { "tripadvisor": true },
  "merge": true
}
```

Mainland what2eat may request `["AMAP"]`; HK/overseas may request `["GOOGLE_MAPS"]` + Tripadvisor enrich — **caller policy**, not agent-hardcoded destination buckets.

## 7. Result model & client navigation

- Cards carry `provider` and/or `sources[]` (id, logo URL, deep links).
- Optional **merge** → one cluster, multiple sources, `primary_provider`.
- **Nav choice is client-side:** e.g. mainland browser prefers AMAP deeplink when present; Google Maps may fail in CN. Agent returns all available links; it does not rewrite UI choice from destination alone.

---

## 8. Tripadvisor enrichment

- Match Tripadvisor by **name + location** (and similar soft signals).
- **Never** pass Google `place_id` (or other Google-native ids) to Tripadvisor as a place identifier.
- Enrichment is optional and best-effort; failures must not wipe primary search results.

## 10. Deployment (野草云3)

**Host:** 野草云3 / `svr_hk_vps_3` (`38.55.192.140`), same ops pattern as release-bot (GHCR → Portainer → Nginx Proxy Manager → Cloudflare). kb-agent is the MCP “Custom Locations” template; mypoke for apex domains where needed.

Admin UI does **not** add a fourth stack (ADR-012). It is packaged in the **places-agent** image.

| Principle | Choice |
| --- | --- |
| Services | **3** independent services (unchanged) |
| Images | **3** images, **one process per image** |
| Portainer | Prefer **3** stacks (isolation / blast radius) |
| places-agent image | Operator web + admin BFF + HTTP API + MCP in that **one** process |
| Avoid | Fourth `places-admin` stack; admin-nginx + agent-API as two processes in one container; map-vendor keys in the image or in the admin UI |

```text
GitHub Actions → GHCR
       ↓
Portainer stack: what2eat          → NPM → what2eat.food
Portainer stack: where2play        → NPM → where2play.place
Portainer stack: places-agent      → NPM → places.agent-mate.ai
       (admin HTML + session APIs + HTTP tools + MCP)
       ↓
Cloudflare
```

**places-agent stack (env and data)**

| Kind | Examples | Where |
| --- | --- | --- |
| Map vendor | AMAP / Google / Tripadvisor | Portainer env — never in admin UI or client bundles |
| Agent LLM | `OPENAI_*` (Quanzil) | Portainer env |
| Mail | Resend API key | Portainer env |
| Admin session | Cookie signing secret | Portainer env |
| Durable store | Admin users, hashed caller API keys | Volume or DB attached to this stack |
| Seed | Default admin `admin` / `me@ethanhuang.com` | First boot; public register remains disabled |

NPM terminates TLS for `places.agent-mate.ai` and proxies **all** paths on that hostname to the one container. MCP Custom Locations (ChatBox `/sse` or `/mcp`) use this same host plus a caller API key issued in the admin app.
