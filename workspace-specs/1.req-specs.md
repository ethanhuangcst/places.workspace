## Purpose

places-agent is a multi-provider place gateway and agent: search, details, navigation helpers, optional enrichment/merge, natural-language place chat, itinerary planning tools, and an **operator management web-app on the same host**. It does **not** own consumer web UX (what2eat / where2play).

- Public host: `places.agent-mate.ai` (operator HTML + HTTP API + MCP)
- **Caller-visible agent id:** `places-agent` (MCP `serverInfo.name`; HTTP JSON `agent`). Not the hostname, not a display title, not localized.
- Callers: what2eat.food, where2play.place, and third parties (e.g. chatboxai.app via MCP)
- Operator app: public home, login, admins, caller API keys, agent instructions (see agent stories Features 14–19)

## Capabilities (tools)

| Tool | Requirement |
| --- | --- |
| `search_restaurants` | Search restaurants by location and criteria via one or more configured place providers |
| `search_places` | Search non-restaurant places (attractions, POIs) the same way |
| `get_place_details` | Fetch details for a known place (provider-native id) |
| `navigate` | Return navigation deep links / URLs for a place (no secrets in links) |
| `plan_itinerary` | Build structured itinerary suggestions from trip bounds and place results (engine lives here; trip UX is caller-owned) |

Supporting behavior (may be internal or exposed as tools later): geocode / reverse-geocode as needed for search; **weather via Open-Meteo** for itinerary / go-out context. Open-Meteo returns English/WMO codes — user-visible weather text must be catalog-translated (`EN` / `CN` / `HK` / `TW`), not passed through ([ADR-014](./adr/ADR-014-open-meteo-weather.md)).

## Provider selection (caller-driven)

- Callers pass which place providers to use for a request (e.g. `providers[]` such as `AMAP`, `GOOGLE_MAPS`, `TRIPADVISOR`).
- places-agent does **not** embed a hard rule that “destination in mainland China ⇒ AMAP only.”
- Agent validates the requested set against configured credentials and capability matrix ([`knowledge/maps/places-capabilities.md`](./knowledge/maps/places-capabilities.md)).
- Unsupported or unconfigured providers → clear error / skip with reason, not silent wrong vendor.
- **`GOOGLE_MAPS` transport:** try direct Google Maps Platform REST first; on **egress failure only**, use the **Cloudflare Worker MCP** (`GMAPS_MCP_*`, Streamable HTTP). Provenance stays `GOOGLE_MAPS`. The Worker is not a fourth `providers[]` id and not an AMAP replacement ([ADR-017](./adr/ADR-017-gmaps-mcp-fallback.md)). Do not fall back to AMAP unless the caller asked for `AMAP`.

## Result contract

- Every place card carries provenance: at least `provider` and/or `sources[]` (provider id, optional logo URL, deep links).
- Optional **merge**: when multiple providers return the same place, return one clustered card with multiple `sources[]` and a `primary_provider`.
- Optional **Tripadvisor enrichment**: enrich Google (or other) results with Tripadvisor ratings/content by **name + location** match — **never** pass Google `place_id` to Tripadvisor as an id.
- UI (caller apps) may show logos from `sources[]` and choose which deep link to open based on **client environment** (e.g. mainland clients prefer AMAP deeplink when present). That preference is **not** enforced inside places-agent as destination geo-policy.

## LLM

- places-agent may use Quanzil (`OPENAI_*`) on **its server** for tool-loop / NL place chat.
- LLM choice is **not** routed by search destination.
- Callers must not send Quanzil or map vendor keys from the browser; apps may hold their own product Quanzil on their BFF (out of scope for this req doc).

## Transports

- **HTTP API** for first-party app BFFs (authenticated **caller API key**).
- **MCP** for agent hosts (same tool semantics as HTTP; same caller API key).
- **Operator web** on the same host: browser → same-origin admin APIs authenticated with an **admin session** (not a caller API key).
- One tool core behind HTTP and MCP. Admin APIs issue and revoke the caller keys those transports check.
- Both channels identify the service as **`places-agent`** (ADR-013).
- The Google Maps **Cloudflare Worker MCP** (`GMAPS_MCP_*`) is an adapter transport for `GOOGLE_MAPS` (ADR-017). It is not this service’s `/mcp` and is not a caller-facing `providers[]` id.
